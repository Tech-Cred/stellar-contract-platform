# Stellar & Soroban Glossary

This glossary defines the Stellar and Soroban domain terms used throughout the
Stellar Contract Observatory codebase and documentation, along with links to
their canonical protocol specifications and corresponding Observatory crates.

---

## Core Protocol & Artifact Terms

### `WASM` (WebAssembly Module)
The compiled binary artifact deployed to the Soroban smart contract runtime.
Soroban contracts compile to the `wasm32-unknown-unknown` (or `wasm32v1-none`)
target and embed contract metadata inside WebAssembly custom sections.
- **Observatory usage:** Inspected statically without execution by
  [`observatory-wasm`](contract-inspection.md).
- **Specification:** [WebAssembly Core Specification](https://webassembly.github.io/spec/core/)

### `WASM Hash` (Contract Code Hash)
The 32-byte SHA-256 digest of the raw deployed contract WASM bytecode stored on
the Stellar ledger (`LedgerEntryData::ContractCode`). On Soroban, deploying a
contract is a two-step process: uploading the WASM bytecode (indexed by its
WASM hash) and instantiating a contract address (`C...`) that references that
hash.
- **Observatory usage:** Computed as `artifact_fingerprint` in
  [`observatory-wasm`](fingerprinting.md) and compared against on-ledger state
  in [`observatory-deployment`](deployment.md) and
  [`observatory-verify`](verification.md).

### `XDR` (External Data Representation — RFC 4506)
The canonical binary serialization format used across the Stellar protocol for
ledger entries, transactions, contract specifications, and events.
- **Observatory usage:** Decoded via the official `stellar-xdr` crate across
  `observatory-spec`, `observatory-events`, and `observatory-deployment`.
- **Specification:** [RFC 4506](https://datatracker.ietf.org/doc/html/rfc4506)
  and [Stellar XDR Definitions](https://github.com/stellar/stellar-xdr)

### `SCVal` (`ScVal`)
The tagged union (`stellar_xdr::ScVal`) representing any dynamically typed
Soroban host value passed into or returned from contract functions, stored in
contract data entries, or emitted in contract events (for example `U32`, `I128`,
`Symbol`, `Vec`, `Map`, `Address`, `Bytes`).
- **Observatory usage:** Decoded and normalized into deterministic JSON
  representations in [`observatory-events`](events.md) and
  [`observatory-deployment`](deployment.md).

### `strkey` (Stellar StrKey Encoding — SEP-0023)
Stellar's Base32-encoded, version-prefixed, CRC16-XModem checksummed string
representation for on-chain identifiers:
- `G...`: Ed25519 public key (Classic account)
- `C...`: Soroban smart contract ID (32-byte hash)
- `S...`: Ed25519 secret seed
- **Observatory usage:** Validated when inspecting deployed contracts in
  [`observatory-deployment`](deployment.md) and [`observatory-verify`](verification.md).
- **Specification:** [SEP-0023: StrKey Encoding](https://github.com/stellar/stellar-protocol/blob/master/ecosystem/sep-0023.md)

## Contract Specification & Metadata Sections

### `contractspecv0`
The WebAssembly custom section embedding a stream of XDR-encoded `ScSpecEntry`
records generated by the `#[contractimpl]` and `#[contracttype]` macros in the
Soroban Rust SDK. It describes every exported contract function, user-defined
type (`struct`, `union`, `enum`, `error enum`), and contract event.
- **Observatory usage:** Extracted by `observatory-wasm` and decoded/normalized
  by [`observatory-spec`](contract-specifications.md).

### `contractmetav0`
The WebAssembly custom section containing a stream of `ScMetaEntry` key-value
pairs (`ScMetaV0`), used by contract authors and build tools (such as
[SEP-0047](https://github.com/stellar/stellar-protocol/blob/master/ecosystem/sep-0047.md))
to record human- and tool-readable metadata (for example `rsver`, `rssdkver`, or
source repository metadata).
- **Observatory usage:** Parsed by [`observatory-verify`](reproducibility.md)
  to inspect build metadata.

### `contractenvmetav0`
The WebAssembly custom section containing `ScEnvMetaEntry` records, specifically
the Soroban host interface version (`ScEnvMetaEntryInterfaceVersion`) against
which the contract WASM was compiled.
- **Observatory usage:** Extracted in [`observatory-wasm`](contract-inspection.md)
  and [`observatory-verify`](verification.md) to check protocol/interface
  compatibility.

### `UDT` (User-Defined Type)
Custom composite types declared in a Soroban contract with `#[contracttype]` or
`#[contracterror]` and serialized into `contractspecv0` as:
- `ScSpecUdtStructV0` (named or tuple structs)
- `ScSpecUdtUnionV0` (tagged unions / Rust `enum` with payloads)
- `ScSpecUdtEnumV0` (integer-discriminant enums)
- `ScSpecUdtErrorEnumV0` (contract error codes mapped to `ScError::Contract`)
- **Observatory usage:** Normalized in [`observatory-spec`](contract-specifications.md)
  and diffed for breaking changes in [`observatory-diff`](interface-diff.md).

## Ledger & Runtime Terms

### `LedgerEntry`
The XDR structure (`stellar_xdr::LedgerEntry`) representing a single state
record in the Stellar ledger. For Soroban contracts, two variants are primary:
- `LedgerEntryData::ContractData`: Holds a contract instance (`ScVal::ContractInstance`,
  which links a `C...` contract ID to its `ContractExecutable::Wasm(Hash)`) or
  persistent/temporary contract storage keys.
- `LedgerEntryData::ContractCode`: Holds the deployed WASM bytecode and its hash.
- **Observatory usage:** Decoded from Soroban RPC `getLedgerEntries` responses
  in [`observatory-deployment`](deployment.md).

### `ContractEvent`
An XDR record (`stellar_xdr::ContractEvent`) emitted by a Soroban contract via
`env.events().publish(topics, data)` during transaction execution. Each event
contains an optional `contract_id`, an event `type_` (`Contract`, `System`, or
`Diagnostic`), a list of `topics` (`Vec<ScVal>`), and a `data` payload (`ScVal`).
- **Observatory usage:** Decoded from JSON fixtures or raw base64 XDR in
  [`observatory-events`](events.md).

## Observatory-Specific Terms

### `Artifact Fingerprint`
The SHA-256 hex digest of the exact `.wasm` file bytes. Any change to bytecode,
custom sections, or compiler flags changes the artifact fingerprint. See
[`fingerprinting.md`](fingerprinting.md).

### `Interface Fingerprint`
The SHA-256 hex digest of the canonical, deterministically ordered JSON
representation of a contract's `ContractInterface` (`functions`, `structs`,
`unions`, `enums`, `error_enums`, `events`), excluding documentation strings.
Two builds with identical public interfaces produce the same interface
fingerprint even if their compiled WASM bytes differ. See
[`fingerprinting.md`](fingerprinting.md).
